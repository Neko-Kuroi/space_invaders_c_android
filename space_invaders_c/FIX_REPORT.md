## 検証の結論（修正前）

- 指摘1（row_counter の停止）: 本物。しかも移植ミスではなく原典 Python 側のバグそのものだった。原典の実コードで再現: 上2行を全滅させ minRow=2、カウンタが 0 または 1 の状態で200ステップ回すと移動ゼロ、カウンタは −199 まで低下。正常系では移動する。残り4体以下で復活する点、reset で戻らない持ち越しも原典共通。
- 指摘2（draw_explosions が状態を書き換える）: C版のコードで確認。現行のメインループでは描画が毎フレーム回るため表面化していないが、設計上の問題として実在。

- 中項目 (f): 原典の groupcollide は自機弾・敵弾とも重なった全セルを消す。C版の (g) は原典どおり全セルだったが、(f) だけ最初の1セルで止めており、原典と違う写し間違いだった。

## 修正内容

### 1. 原典 Python（~/workspace/space_invaders/spaceinvaders.py）— 先に修正

- `EnemiesGroup.update` の包み直し条件を `ROW_counter == minRow - 1` から `<=` に変更（飛び越えても包み直して復帰する）。
- `SpaceInvaders.reset()` で `ROW_counter = 4` に戻すようにした（持ち越しの防止）。
- 回帰テストを新規追加: `tests/test_rowcounter_fix.py`（5件）。修正前は4件不合格（正常系の確認だけ合格）、修正後は全件合格。
- 全テスト: 20件合格（従来の15件＋新規5件）。仮想時計でのメインループ相当 3,600 フレームの実走も例外なし。

### 2. C版 — 指摘1の反映

- 包み直しの規則を `logic.c` の純関数 `fleet_counter_advance()` に切り出し、`game.c` の `fleet_update` がそれを使う形にした（SDL 非依存なのでテスト可能）。
- `reset_round()` で `row_counter = 4` に戻す。
- テスト追加7件（通常巡回、一番下での包み直し、上の行全滅直後の包み直し、止まるパターンの回帰2件、大きく負に沈んだ状態からの復帰）。logic テストは 60件 → 67件、全合格。

### 3. C版 — 指摘2（爆発の消滅判定）

- 消滅判定を `explosions_update()` として更新側に新設し、`game_update` のプレイ中分岐（原典で explosionsGroup.update が呼ばれる位置）から呼ぶ。
- `draw_explosions` は状態を書き換えず、時間窓で描くかどうかだけを決める。

### 4. C版 — 指摘3（ミステリー音）

- `main.c` の起動時に `Mix_ReserveChannels(1)` でチャンネル0を予約。
- 出現音は `assets_play_on()`（新設）で専用チャンネル `MYSTERY_CHANNEL`（game.h、0番）に鳴らす。通常の効果音はこのチャンネルを使わないため、以後のフェードアウト／停止が別の音にかかることはない。

### 5. C版 — (f) の全セル消去と共通化

- 自機弾・敵弾のトーチカ／地面判定を `bullets_vs_blockers()` に共通化し、どちらも重なった全セルを消す（原典どおり）。敵弾のときだけ弾の爆発を出す点は従来どおり。
- ついでに `check_collisions` 末尾の不要な `(void)now;` を削除。
