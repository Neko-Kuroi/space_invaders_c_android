## 1. 目的と前提

- Neko-Kuroi の space_invaders のうち、原典 `spaceinvaders.py`（pygame 版、こちらの修正済みのもの）を仕様の正本として、C 言語へ移植する。
- 位置づけはこれまでの多言語移植と同じで、同一仕様を別の言語で実装して比べることが目的。見た目や挙動は原典に合わせ、言語の都合で必要な設計の置き換えは明示する。
- 対象環境は Linux（この VM と Satoru の手元）。コンパイラは gcc、ビルドは make。
- 本家のリポジトリ（~/workspace/space_invaders）には混ぜない。C 版は独立フォルダで作り、取り込みの判断は完成後にする。
- 素材は原典のものをそのまま流用する: images/（png・jpg）、sounds/（wav 10点）、fonts/space_invaders.ttf。新しい素材は作らない。

## 2. 技術選定: SDL2

C には画面・音の標準手段が無いため、pygame の裏側で動いている SDL2 を土台にする。

| pygame（原典） | C 版（SDL2 系） |
|---|---|
| 画像の読み込み・表示（Surface） | SDL2 本体 ＋ SDL2_image（png / jpg） |
| 画面への描画 | SDL_Renderer ＋ SDL_Texture |
| 音（mixer.Sound） | SDL2_mixer（wav） |
| 文字（font.Font） | SDL2_ttf |
| キー入力（key / event） | SDL_Event、SDL_GetKeyboardState |
| 時間（time.get_ticks） | SDL_GetTicks |
| 矩形と当たり判定（Rect、groupcollide） | SDL_Rect、SDL_HasIntersection ＋ 自前の走査 |
| スプライトとグループ | 構造体 ＋ 固定長配列の自前管理（第5節） |
| 画面の SCALED 表示 | SDL_RenderSetLogicalSize(800, 600) |

代替候補の raylib は短く書けるが、原典との部品対応が SDL2 ほど素直でなく、比較研究という目的には SDL2 が合うため採らない。

環境メモ: この VM には gcc / make / pkg-config はあるが、SDL2 の開発パッケージは未導入であることを確認済み。Phase 0 で `libsdl2-dev libsdl2-image-dev libsdl2-mixer-dev libsdl2-ttf-dev` を入れる（Satoru の手元でも同じ導入が要る）。

## 3. 仕様の要点（原典から抜き出した数値）

- 画面: 800×600。背景画像あり。色は原典の定義どおり（GREEN=(78,255,87) など6色）。
- 自機: 50×50、初期位置は左上 (375, 540)。残機3。移動は A / D（原典は K_a / K_d）。キー離しで速度リセット（check_input と対）。
  - 移動の癖（再現対象）: キーを押している間 vx が毎フレーム +1 ずつ増え、位置は「目標との差の 1/3」ずつ寄る。SHIP_VX = 10 が初期値。端は x=10 と右端で止まる。
- 発射: S キー。自機弾は同時に1発まで（武器強化時はその限りでない）。弾速は上向き 15、下向き（敵弾）は 10。
  - 武器の段階: スコア 1990 以下は単発、1990〜3500 未満は2発、3500 以上は3発。ラウンド6以降はスコアによらず3発。
- 敵: 5行×10列＝50体。画像は 40×35 に縮小して使う。配置は x = 157 + 列×50、y = enemyPosition + 行×45（enemyPosition の初期値は 65）。
  - 得点: 行ごとに {0行:30, 1行:20, 2行:20, 3行:10, 4行:10}。
  - 移動: 水平ステップ 10px、下降は 35px（ENEMY_MOVE_DOWN）。左右の移動回数は基本30回ずつで、端の列が全滅するとその分が反対側に加算される（leftAddMove / rightAddMove）。moveNumber の初期値は 15。
  - 波状の動き（再現対象）: 1回の移動タイミングで全行が一斉には動かず、ROW_counter が指す行だけが動き、行を下から順に巡る。残り4体以下では全員が毎回動く。
  - 速度: EnemiesGroup.moveTime が間隔（初期 200ms）。残数が減ると update_speed の表で速くなる（1体で 2ms かつ LEVEL=350、など表の全段を写す）。各敵のタイマーは timeOffset = 行×(-50) + 列×120 でずらす（描画のちらつき防止側の仕組みで、実移動はグループ側）。
  - ラウンドが上がると集団のタイマーが timeOffset = 22000 × ROUND_NUM だけ過去から始まる（再現対象）。実測では、これは出現の遅れではなく「追いつきの速進」として現れる: ラウンド2以降、開始直後は毎フレーム移動ステップが走り（120フレームで約119ステップ、ラウンド1は9ステップ）、方向反転と35pxの下降が序盤にまとめて起きる。タイマーは1フレームに最大1ステップ、`timer += moveTime` で追いつく原典の式のまま写す。enemyPosition 自体は毎回 65 に戻る（原典のコメントアウトされた「+= ENEMY_MOVE_DOWN」は無効のまま）。
- 敵の発射: LEVEL=700ms 間隔で、一番下の列…ではなく「生きている列から無作為に1列、その列の一番下の敵」が撃つ（random_bottom）。敵弾がトーチカや自機に当たると 300ms の爆発表示。
- トーチカ: 4基。設計表（16行×26列、うち先頭行は空、ブロックのある行は15行）の 1 のセルに 3×3 のブロックを置く。位置は x = 60 + 200×基数 + 列×3、y = 450 + 25 + 行×3、色は RED。1基318セル×4基＋地面800（4px×200、y=595、原典では4基分が重なって生成されるが同一位置なので1本で等価）で、総ブロック数は 2,072 個（原典で実測）。自機弾・敵弾の両方で削れる。
- ミステリーシップ: 80×40、開始位置 (-80, 25)。25,000ms 周期で右へ 2px/フレーム進む。出現時に mysteryentered.wav（音量 0.1、4秒フェードアウトの癖あり）。撃墜時の得点は {50, 100, 150, 300} から無作為。得点は画面に 500ms 表示（MysteryExplosion 相当）。
- 撃墜・被弾の演出: 敵の爆発は行の色に対応（explosionblue/green/purple）。自機の爆発は3枚の画像を時間で切り替え、再出撃までの流れは create_new_ship の時間窓（200/300/400ms 区切り）のとおり。
- ゲームオーバー表示: 専用タイマー基準で、900ms から 100ms 刻みに文字が増え、1700ms で全文、4000ms 超でタイトルへ戻る（原典の F-5 修正済みの形を正とする）。
- 音楽: 0.wav〜3.wav の4音を、敵の移動間隔×3 の周期で順に鳴らす（noteIndex が 0→3 を循環）。
- 終了: ウィンドウを閉じる、または原典の should_exit の条件（ESC 等…原典の実装を確認して写す）。

数値の正本は原典のコードそのもの。本節は計画のための要約で、実装時に食い違いがあれば原典が優先する。

## 4. 原典の癖の扱い

「再現する」と決めたものは第3節に（再現対象）と書いた。以下は言語の都合で置き換えるもの:

- 全域の `game` オブジェクト経由の相互参照 → ゲーム状態を1つの構造体（Game）にまとめ、ポインタで渡す。C ではこれが自然な形で、import 時 NameError のような問題も起きない。
- スプライトグループと groupcollide → 固定長配列と二重ループの走査。対象の総数が小さい（敵50、弾は少数、トーチカ2,072）ため性能上の問題はない。
- 例外や動的な型は使わない。乱数は rand() に SDL_GetTicks 等で種を与える（原典は Python の random）。

## 5. 設計方針

- ファイル構成（案）:
  - `src/main.c` — SDL の初期化、メインループ、入力
  - `src/game.c / game.h` — ゲーム状態（Game 構造体）と進行管理（タイトル／プレイ／ゲームオーバー／ラウンド遷移）
  - `src/entities.c / entities.h` — 自機・敵集団・弾・トーチカ・ミステリーシップの更新と描画
  - `src/logic.c / logic.h` — 画面に依存しない純ロジック: 敵の台帳（生きている列・左右端）、速度表、得点表、射手の選択。ここだけ単体テストできる形にする
  - `src/assets.c / assets.h` — 画像・音・フォントの読み込みと解放
  - `tests/test_logic.c` — logic の単体テスト（台帳の更新、速度表、得点表）
  - `Makefile` — `make` で実行ファイル `space_invaders_c` を作る。素材は実行時に相対パスで読む
- メモリ管理: 動的割り当ては最小限にし、上限の決まっているもの（敵50、トーチカ2,072セル、弾・爆発の同時数）は固定長配列で持つ。テクスチャ等の SDL オブジェクトだけ生成・破棄の対を assets に閉じ込める。
- 時間の扱い: 原典と同じく SDL_GetTicks() 基準の絶対時刻で進める（フレーム数依存にしない）。メインループは 60fps 目安に SDL_Delay で調整。
- 想定規模: 2,000〜2,500行程度（原典860行の約3倍）。
